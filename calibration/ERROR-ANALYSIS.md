# Why Marlo's engine is wrong on real pages

Generated by `node scripts/error-analysis.mjs` from `real-marlo-verdicts.json` and the resolved cells in `corpus/real/adjudication/`. Do not edit.

On the 1023 resolved real-page cells, Marlo's own engine reports 27 false positives and 43 false negatives among the rules it evaluates. A further 34 failures fall on rules it cannot evaluate without layout, and count against its recall in the calibration table. Every wrong cell is listed below with what Marlo said, what both raters said, and a root cause. The ground truth is model-adjudicated; see `corpus/real/adjudication/RATER-VALIDITY.md` for how accurate that process is.

## Findings

1. **Rule logic, not the renderer, causes most false positives.** 17 of 27 come from rule logic that contradicts the ACT rule text. 10 come from the static renderer, which does no layout and so cannot see that a stylesheet hides an element.
2. **One defect causes 8 false positives.** Marlo fails an ID reference whose target is missing, which the rule explicitly allows.
3. **Most false negatives are abstentions.** 24 of 43 are cells where Marlo answered cantTell, mostly because a bypass rule depends on what repeats across pages, or because whether an image is decorative is a judgment. Strict grading counts an abstention on a failure as a miss.
4. **The ACT suite does not catch these.** 5 rules with real-page errors (2ee8b8, 4e8ab6, 5f99a7, 674b10, b40fd1) score perfectly on their ACT test cases, because no test case exercises the construct that fails here.
5. **A browser renderer would change the picture.** Rerun in headless Chromium, Marlo's precision is 0.733 against 0.372, and its recall 0.473 against 0.172. Most of the recall comes from rules that need layout. Chromium removes 13 of the 27 false positives and introduces 3 new errors. This compares Marlo with itself; the comparison between engines in the calibration table uses the static renderer for all four.

"Perfect on ACT" lists the rules among them that Marlo gets entirely right on the ACT test cases. "Chromium corrects" counts the cells the browser renderer gets right.

### Cannot tell what repeats across pages

Bypass rules turn on whether a block repeats on other pages of the site, which one page cannot show. Marlo answers cantTell; the raters judged the site header repeated and found no skip link, landmark or other way past it.

### Looks only at img elements, not inline svg

The failing images are inline `svg` elements (a licence logo, a close icon, a store logo) that are `aria-hidden` or have no name. Marlo finds no applicable image and answers inapplicable.

### Cannot tell whether a hidden image is decorative

Whether an image hidden from assistive technology carries information is a judgment about its content. Marlo asks for a person to check; the raters found brand logos, close glyphs and a search icon whose meaning was otherwise lost.

### Abstains on a link named only by an image

A link holds only an `img` with no alt or an `svg` with no title, so its name is empty. Marlo abstains because an image contributes to the name and it does not trust the renderer's answer, which costs a failure the raters found unambiguous.

### Passes any main landmark

Marlo passes when a main landmark exists. The rule needs a landmark whose first perceivable content is non-repeated, and on these pages `main` opens with the repeated header or logo.

### Accepts aria-description, which ARIA 1.2 does not define

The ACT rule pins WAI-ARIA 1.2. `aria-description` exists only in the 1.3 draft, and Marlo's attribute list includes it. Browsers support it, so this is a disagreement about the specification version more than a defect.

### Does not compute the implicit role of every element

`aria-expanded` on a `label` and on a `span` with no role is not permitted. Deciding that needs the implicit role, which Marlo does not compute for every element, so it abstains.

### Misses an owned element of the wrong role

A list owns headings and separators, and a table owns a `caption`, which ARIA 1.2 does not list among its required owned elements. Marlo passes the list and finds the table inapplicable.

### Fails an ID reference whose target is missing

Marlo fails `aria-controls`, `aria-labelledby` or `aria-describedby` when no element has the referenced id. The ACT rule says, as an exception, that ID Reference values need no referenced element, and leaves missing targets to a separate rule (in6db8). On three pages the target does exist and the static renderer lost it, which only adds to the count.

### Evaluates an element a stylesheet hides

A listbox, menu, search field or button is hidden by a page stylesheet. The static renderer does no layout and reports it as present, so Marlo checks something nobody can perceive. In headless Chromium the element is hidden and the error goes away.

### Ignores display:none when deciding applicability

Links inside a `display:none` panel are counted as focusable content of an `aria-hidden` region (6cfa84), and `display:none` buttons are checked for their visible label (2ee8b8). The browser renderer resolves the style and Marlo still flags them, so the rule, not the renderer, skips the visibility test.

### Cannot see CSS generated content in a name

Citation backlinks are named only by a `::before` counter (a, b, c). The accessible name computation includes generated content; the static renderer has none, so the links look unnamed. In Chromium Marlo abstains instead of failing.

### Misses the abbreviation exception in label-in-name

The visible labels "EN" and "UI Designer" contain abbreviations, which the rule's applicability excludes. Marlo applies the rule and fails both links.

### Does not accept a placeholder as an accessible name

HTML-AAM lets `placeholder` supply a name when nothing else does, so the field has a non-empty name and passes. Marlo treats the placeholder as no name. It is weak labelling, but the rule asks only for a non-empty name.

### Does not know DPUB-ARIA roles

`role="doc-noteref"` is a valid DPUB-ARIA role, which the rule counts. Marlo checks only the WAI-ARIA role list.

### Requires aria-valuenow on a non-focusable separator

Only a focusable separator is a widget with required value properties. Marlo requires `aria-valuenow` on an `li role="separator"` that is not focusable.
